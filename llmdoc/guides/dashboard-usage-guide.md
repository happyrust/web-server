# 增量更新实时监控仪表盘使用指南

## 1. 快速开始

### 1.1 启动服务

```bash
# 启动Web服务器
cargo run --bin web_server --features web_server

# 访问仪表盘
打开浏览器访问: http://localhost:8080/dashboard
```

### 1.2 页面概览

仪表盘包含以下主要区域：

- **统计卡片区** - 顶部4个卡片显示关键指标
- **失败任务队列** - 错误恢复系统的状态概览
- **活跃任务列表** - 当前正在执行的增量更新任务
- **趋势图表区** - 三个Chart.js可视化图表
- **最近事件流** - 系统最新活动日志

## 2. 核心功能使用

### 2.1 实时监控

#### 查看统计卡片

页面顶部显示4个实时统计指标：

- **进行中**: 当前正在执行的增量更新任务数
- **今日完成**: 今天已成功完成的任务数
- **今日失败**: 今天失败的任务数（需要关注）
- **成功率**: 总体成功率百分比

**刷新机制:**
- 自动刷新：每30秒自动更新
- 手动刷新：点击右上角"刷新"按钮

#### 监控活跃任务

活跃任务列表显示：
- 任务名称和文件路径
- 当前状态（Pending/Running/Completed/Failed）
- 实时进度条（0-100%）

**实时更新:**
- 通过WebSocket推送，延迟<1秒
- 进度条平滑动画过渡

### 2.2 趋势图表分析

#### 任务趋势图（面积图）

**功能:**
- 绿色区域：成功任务数量
- 红色区域：失败任务数量
- 横轴：时间轴
- 纵轴：任务数量

**时间窗口切换:**
1. 点击图表右上角的下拉菜单
2. 选择时间范围：
   - 最近1小时（5分钟间隔）
   - 最近24小时（1小时间隔）
   - 最近7天（6小时间隔）
   - 最近30天（1天间隔）
3. 图表自动重新加载数据

**用途:**
- 识别高峰时段
- 发现异常失败集中期
- 评估系统负载

#### 成功率趋势图（折线图）

**功能:**
- 蓝色折线：成功率百分比（0-100%）
- 显示成功率随时间的变化

**用途:**
- 快速判断系统健康度
- 发现成功率下降的时间点
- 评估系统稳定性

#### 平均耗时图（柱状图）

**功能:**
- 紫色柱状：每个时间段的平均任务耗时（秒）

**用途:**
- 识别性能瓶颈
- 发现慢任务时段
- 优化资源分配

### 2.3 失败任务管理

#### 打开失败任务详情

1. 找到"失败任务队列"卡片
2. 点击"查看详情"按钮
3. 模态框打开，显示所有失败任务

#### 过滤失败任务

**按类型过滤:**
- 所有类型
- 数据库查询失败
- CBA压缩失败
- 增量更新失败
- MQTT推送失败

**按状态过滤:**
- 所有状态
- 待重试（即将自动重试）
- 已耗尽（需要人工介入）

**操作步骤:**
1. 在模态框顶部选择过滤条件
2. 列表自动刷新显示匹配结果

#### 查看任务详情

每个失败任务显示：
- 任务类型和描述
- 错误信息（红色文字）
- 重试次数（如 "2/5" 表示已重试2次，最多5次）
- 首次失败时间
- 下次重试时间（如果未耗尽）

**查看元数据:**
1. 点击任务下方的"查看元数据"
2. 展开显示JSON格式的详细信息
3. 包含文件路径、会话号范围等上下文

#### 手动重试任务

1. 找到需要重试的任务
2. 点击任务右侧的"重试"按钮
3. 任务立即加入重试队列
4. 系统显示"任务已加入重试队列"提示
5. 任务列表和统计卡片自动更新

**适用场景:**
- 临时故障已修复，需要立即重试
- 不想等待自动重试的时间间隔
- 测试修复是否有效

#### 清理已耗尽任务

1. 点击"失败任务队列"卡片的"清理已耗尽"按钮
2. 确认对话框弹出：`确定要清理所有已耗尽的失败任务吗？`
3. 点击"确定"
4. 系统删除所有达到最大重试次数的任务
5. 显示清理结果：`已清理 X 个已耗尽的任务`

**警告:**
- 清理前请确认这些任务的数据已恢复或可以丢弃
- 清理后无法恢复
- 建议先查看任务详情，记录重要信息

## 3. 数据解读

### 3.1 统计指标含义

| 指标 | 计算方式 | 健康阈值 |
|------|----------|----------|
| 进行中 | 当前Running状态任务数 | <10 |
| 今日完成 | 今天Completed状态任务数 | - |
| 今日失败 | 今天Failed状态任务数 | <5% |
| 成功率 | 成功数/(成功数+失败数)*100% | >95% |

### 3.2 失败任务状态

**待重试 (Pending Retry):**
- 重试次数 < 最大重试次数
- 当前时间 >= 下次重试时间
- 系统会自动重试

**等待中 (Waiting):**
- 重试次数 < 最大重试次数
- 当前时间 < 下次重试时间
- 等待下次重试时间到达

**已耗尽 (Exhausted):**
- 重试次数 >= 最大重试次数（默认5次）
- 系统不再自动重试
- 需要人工介入处理

### 3.3 指数退避策略

失败任务的重试时间间隔：

| 重试次数 | 延迟时间 | 累计等待 |
|---------|---------|----------|
| 第1次 | 1分钟 | 1分钟 |
| 第2次 | 2分钟 | 3分钟 |
| 第3次 | 4分钟 | 7分钟 |
| 第4次 | 8分钟 | 15分钟 |
| 第5次 | 16分钟 | 31分钟 |

**设计原因:**
- 短暂故障快速恢复（1分钟）
- 持续故障避免系统负担（最长16分钟）
- 覆盖约31分钟的恢复窗口

## 4. 常见使用场景

### 4.1 日常监控

**操作流程:**
1. 早上打开仪表盘
2. 查看"今日完成"和"成功率"
3. 检查"已耗尽"任务数（应为0）
4. 浏览"最近事件"确认无异常

**频率:** 每天1-2次

### 4.2 故障排查

**场景:** 成功率突然下降

**步骤:**
1. 查看"任务趋势图"确定故障时间段
2. 点击"查看详情"查看失败任务
3. 按类型过滤，找到主要失败类型
4. 查看错误信息，确定根本原因
5. 修复问题后，手动重试失败任务

### 4.3 性能优化

**场景:** 任务执行缓慢

**步骤:**
1. 查看"平均耗时图"识别慢时段
2. 对比"任务趋势图"查看该时段负载
3. 检查是否存在资源竞争
4. 调整调度策略或增加资源

### 4.4 定期维护

**每周任务:**
- 清理已耗尽的失败任务
- 检查7天趋势，评估系统稳定性
- 导出关键指标（如需要）

**每月任务:**
- 查看30天趋势，识别长期模式
- 评估成功率是否达标（>95%）
- 记录性能基线数据

## 5. 故障处理

### 5.1 页面无法加载

**症状:** 访问 `/dashboard` 返回404或500错误

**解决方案:**
1. 检查Web服务是否启动
   ```bash
   curl http://localhost:8080/api/dashboard/summary
   ```
2. 查看服务器日志中的错误信息
3. 确认 `web_server` feature已启用
4. 重启Web服务器

### 5.2 图表不显示

**症状:** 页面加载但图表区域为空

**解决方案:**
1. 打开浏览器开发者工具（F12）
2. 查看Console是否有JavaScript错误
3. 检查Chart.js CDN是否加载成功
   ```
   查看Network标签，搜索 "chart.js"
   ```
4. 确认数据库中有历史数据
   ```sql
   SELECT COUNT(*) FROM remote_sync_logs;
   ```

### 5.3 WebSocket连接失败

**症状:** 统计数据不实时更新

**解决方案:**
1. 打开浏览器Console查看WebSocket错误
2. 检查服务器日志中的WebSocket相关日志
3. 确认防火墙未阻止WebSocket连接
4. 刷新页面重新建立连接

### 5.4 数据不准确

**症状:** 显示的统计数据与实际不符

**解决方案:**
1. 点击"刷新"按钮手动刷新
2. 检查数据库连接状态
3. 查看 `deployment_sites.sqlite` 文件权限
4. 确认 `FailedTaskQueue` 持久化文件存在
   ```bash
   ls -lh assets/failed_tasks.json
   ```

## 6. 最佳实践

### 6.1 监控策略

**主动监控:**
- 设置浏览器书签，快速访问仪表盘
- 每天固定时间查看（如早上9点）
- 关注成功率和失败任务趋势

**被动监控:**
- 依赖WebSocket实时推送
- 保持页面在后台标签打开
- 接收浏览器通知（未来功能）

### 6.2 数据保留

**失败任务:**
- 定期清理已耗尽任务（建议每周）
- 清理前导出重要信息
- 保留最近30天的失败任务

**历史数据:**
- SQLite数据库自动保留所有历史
- 建议每月备份 `deployment_sites.sqlite`
- 大型部署考虑定期归档旧数据

### 6.3 性能优化

**浏览器:**
- 使用现代浏览器（Chrome/Edge/Firefox最新版）
- 启用硬件加速
- 定期清理浏览器缓存

**服务器:**
- 确保SQLite数据库有足够磁盘空间
- 监控内存使用（FailedTaskQueue在内存中）
- 定期重启服务器释放资源（可选）

## 7. API参考（高级用户）

### 7.1 REST API端点

```
GET  /api/dashboard/summary
     返回仪表盘概览统计

GET  /api/dashboard/active-tasks
     返回活跃任务列表

GET  /api/dashboard/failed-tasks?task_type=X&pending_only=true
     返回失败任务（支持过滤）

GET  /api/dashboard/stats/timeline?window=24h
     返回时间线统计数据

POST /api/dashboard/retry-task/:id
     手动重试指定任务

POST /api/dashboard/cleanup-exhausted
     清理所有已耗尽任务
```

### 7.2 WebSocket端点

```
WS /ws/tasks
   订阅所有任务状态更新

消息格式:
{
  "type": "TaskStatusChange" | "StatsUpdate" | "NewFailedTask",
  "data": { ... }
}
```
