# 从节点自动订阅主节点实现方案

## 问题分析

### 当前问题
1. **站点添加时缺少主节点信息**：添加站点时只保存基本信息（name, location, http_host等），没有记录主节点的MQTT服务器信息
2. **从节点启动时无法自动订阅**：从节点启动时，MQTT配置来自 `DbOption.toml`，但无法知道应该订阅哪个主节点
3. **配置分散**：主节点信息分散在环境配置和站点配置中，缺乏统一管理

### 目标流程
```
主节点添加从节点
  ↓
获取主节点的MQTT配置（mqtt_host, mqtt_port）
  ↓
将主节点MQTT信息保存到站点记录中
  ↓
通知被添加的从站点（可选：通过HTTP API）
  ↓
从站点启动时
  ↓
读取站点配置中的主节点MQTT信息
  ↓
自动连接到主节点MQTT服务器并订阅
```

## 实现方案

### 1. 数据库表结构扩展

在 `remote_sync_sites` 表中添加主节点MQTT配置字段：

```sql
ALTER TABLE remote_sync_sites ADD COLUMN master_mqtt_host TEXT;
ALTER TABLE remote_sync_sites ADD COLUMN master_mqtt_port INTEGER;
```

**字段说明**：
- `master_mqtt_host`: 主节点的MQTT服务器地址（从节点需要连接的目标）
- `master_mqtt_port`: 主节点的MQTT服务器端口（默认1883）

### 3. 站点创建逻辑改进

#### 3.1 主节点添加从节点时的处理

当主节点添加从节点时，自动填充主节点的MQTT信息：

```rust
/// 创建站点（自动填充主节点MQTT信息）
pub async fn create_site(
    Path(env_id): Path<String>,
    Json(mut req): Json<SiteCreateRequest>,
) -> Result<Json<serde_json::Value>, StatusCode> {
    // 如果未提供主节点MQTT信息，尝试从当前站点配置获取
    if req.master_mqtt_host.is_none() {
        use aios_core::get_db_option;
        let db_option = get_db_option();
        
        // 检查当前站点是否为主节点（通过检查是否有MQTT Broker运行）
        // 或者从环境配置中获取
        if let Some(env) = get_env_by_id(&env_id).await.ok().flatten() {
            if let Some(mqtt_host) = env.mqtt_host {
                req.master_mqtt_host = Some(mqtt_host);
                req.master_mqtt_port = env.mqtt_port.or(Some(1883));
            }
        } else {
            // 如果环境配置中没有，使用当前站点的MQTT配置
            req.master_mqtt_host = Some(db_option.mqtt_host.clone());
            req.master_mqtt_port = Some(db_option.mqtt_port);
        }
    }
    
    // 调用内部创建函数
    match create_site_internal(&env_id, req).await {
        Ok(site_id) => {
            // 可选：通知被添加的从站点（通过HTTP API）
            notify_slave_site_configured(&site_id).await.ok();
            
            Ok(Json(json!({
                "status": "success",
                "site_id": site_id,
                "message": "站点创建成功，已配置主节点MQTT信息"
            })))
        }
        Err(e) => Err(StatusCode::INTERNAL_SERVER_ERROR)
    }
}
```

#### 4.2 添加获取主节点MQTT配置的函数

```rust
/// 获取当前站点的主节点MQTT配置
async fn get_master_mqtt_config() -> anyhow::Result<Option<(String, u16)>> {
    use aios_core::get_db_option;
    use crate::web_server::remote_sync_handlers;
    
    let db_option = get_db_option();
    let current_location = db_option.location.clone();
    
    // 查询当前站点的主节点MQTT配置
    let conn = remote_sync_handlers::open_sqlite()?;
    let mut stmt = conn.prepare(
        "SELECT master_mqtt_host, master_mqtt_port 
         FROM remote_sync_sites 
         WHERE location = ?1 
         LIMIT 1"
    )?;
    
    let result = stmt.query_row(
        rusqlite::params![current_location],
        |row| {
            let host: Option<String> = row.get(0)?;
            let port: Option<i64> = row.get(1)?;
            Ok((host, port))
        }
    ).optional()?;
    
    if let Some((Some(host), Some(port))) = result {
        Ok(Some((host, port as u16)))
    } else {
        Ok(None)
    }
}
```

#### 4.3 修改MQTT客户端创建逻辑

需要支持动态MQTT配置，而不是只从 `DbOption.toml` 读取：

```rust
/// 创建MQTT实例（支持动态配置）
pub fn new_mqtt_instance_with_config(
    id: &str,
    mqtt_host: Option<String>,
    mqtt_port: Option<u16>,
) -> MqttInstance {
    let db_option = get_db_option();
    
    // 优先使用传入的配置，否则使用默认配置
    let host = mqtt_host.unwrap_or_else(|| db_option.mqtt_host.clone());
    let port = mqtt_port.unwrap_or(db_option.mqtt_port);
    
    let mut mqttoptions = MqttOptions::new(id, host.as_str(), port);
    mqttoptions.set_clean_session(false);
    mqttoptions.set_keep_alive(Duration::from_secs(500));
    
    let (client, el) = AsyncClient::new(mqttoptions, 5000);
    MqttInstance { client, el }
}
```

### 5. 通知机制（可选）

当主节点添加从节点时，可以通过HTTP API通知从站点：

```rust
/// 通知从站点配置已更新
async fn notify_slave_site_configured(site_id: &str) -> anyhow::Result<()> {
    // 1. 查询站点信息
    let site = get_site_by_id(site_id).await?;
    
    // 2. 如果从站点有 http_host，发送通知
    if let Some(http_host) = site.http_host {
        let client = reqwest::Client::new();
        let url = format!("{}/api/site-config/notify-master-updated", http_host);
        
        let _ = client
            .post(&url)
            .json(&json!({
                "master_mqtt_host": site.master_mqtt_host,
                "master_mqtt_port": site.master_mqtt_port,
            }))
            .timeout(Duration::from_secs(5))
            .send()
            .await;
    }
    
    Ok(())
}
```

## 注意事项

1. **向后兼容**：新字段为可选，不影响现有站点
2. **配置优先级**：
   - 站点配置中的 `master_mqtt_host/port`（最高优先级）
   - 环境配置中的 `mqtt_host/port`
   - `DbOption.toml` 中的默认配置
3. **主节点判断**：可以通过检查是否有MQTT Broker运行来判断，或通过配置标记
4. **错误处理**：如果主节点MQTT配置无效，应记录错误并回退到默认配置
