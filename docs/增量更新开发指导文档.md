## 1. 系统概述

### 1.1 功能定位

增量更新系统是异地同步架构的核心组件，负责：

- 📁 **文件监听**: 实时监控PDMS数据库文件的变化
- 🔍 **增量检测**: 通过会话号对比识别数据变化
- 📦 **数据收集**: 提取指定会话号范围内的增量元素
- 💾 **数据库同步**: 将增量更新到SurrealDB
- 📮 **远程通知**: 通过MQTT推送同步消息
- 🚀 **任务调度**: 触发远程文件同步任务

### 1.2 技术架构

## 2. 核心概念

### 2.1 会话号 (Session Number, sesno)

**定义**: PDMS数据库中每次数据修改都会生成一个递增的会话号，用于标识数据版本。

**作用**:
- 数据版本控制的唯一标识
- 增量检测的核心依据
- 支持时间点数据恢复

**存储位置**:
- **文件中**: PDMS数据库文件头部 `DbPageBasicInfo.latest_ses_data.sesno`
- **数据库中**: SurrealDB的 `dbnum_info_table` 表，每个元素的 `sesno` 字段

**示例**:
```rust
// 文件会话号
let file_sesno = 12350;

// 数据库会话号 (查询获取)
let db_sesno = query_latest_sesno_by_dbnum(7997).await?; // 返回 12340

// 增量范围
let increment_range = (db_sesno + 1)..=file_sesno; // 12341..=12350
```

### 2.2 增量检测机制

**双源对比策略**:

```
文件会话号 (file_sesno)  vs  数据库会话号 (db_sesno)
        ↓                            ↓
  从PDMS文件头读取              从SurrealDB查询
        ↓                            ↓
        └────────── 对比 ──────────┘
                    ↓
            if file_sesno > db_sesno:
                有增量 ✅
                范围 = (db_sesno+1)..=file_sesno
            else:
                无增量 ⏭️
                跳过处理
```

**判断逻辑**:
```rust
// 从文件读取
let file_sesno = new_header.latest_ses_data.sesno;

// 从数据库查询
let db_sesno = Self::query_latest_sesno_by_dbnum(db_num).await?;

// 对比判断
if file_sesno > db_sesno {
    // 有增量，构建处理范围
    let range = (db_sesno + 1)..=file_sesno;
    params.insert(path, (header, range));
} else {
    // 无增量，跳过
    continue;
}
```

### 2.3 增量元素操作类型

**EleOperation枚举**:

```rust
pub enum EleOperation {
    Add,      // 新增元素
    Modified, // 修改元素属性
    Deleted,  // 删除元素
}
```

**处理策略**:
- `Add`: INSERT到数据库
- `Modified`: UPDATE数据库中已有记录
- `Deleted`: DELETE数据库记录

### 2.4 CBA压缩包

**定义**: Compressed Binary Archive，PDMS数据库的压缩格式，用于网络传输。

**生成时机**:
1. 系统启动时为所有监听文件生成初始CBA
2. 检测到增量更新后重新生成
3. 新增文件时生成

**存储路径**: `assets/archives/{文件名}.cba`

**用途**:
- 远程站点HTTP下载
- 文件完整性校验 (SHA256 hash)
- 减少网络传输量

### 3.3 增量更新执行流程 (execute_incr_update)

**代码位置**: `src/data_interface/increment_manager.rs:421-447`

**执行步骤**:

```
START: execute_incr_update(params)
│
├─ 参数: IndexMap<PathBuf, (DbPageBasicInfo, RangeInclusive<i32>)>
│   └─ 每个条目: (文件路径, (文件头信息, 会话号范围))
│
└─ 遍历每个文件
    │
    for (path, (basic_info, sesno_range)) in params:
    │
    ├─ 步骤1: 打开PDMS文件
    │   ├─ PdmsIO::new("", path, true)
    │   └─ io.open()
    │
    ├─ 步骤2: 收集增量元素
    │   ├─ io.collect_increment_eles(Some(sesno_range))
    │   ├─ 输入: 会话号范围 (例如: 12341..=12350)
    │   └─ 输出: Vec<EleOperationData>
    │       └─ 每个元素包含:
    │           ├─ refno (引用编号)
    │           ├─ operation (Add/Modified/Deleted)
    │           ├─ attr (属性映射)
    │           └─ children (子元素列表)
    │
    ├─ 步骤3: 更新到数据库
    │   ├─ io.update_elements_to_database(&eles, true).await
    │   ├─ 分批处理 (每批200个元素)
    │   └─ 执行INSERT/UPDATE/DELETE操作
    │
    └─ 步骤4: 更新会话号书签
        ├─ end_sesno = sesno_range.end()
        ├─ file_name = path.file_stem()
        └─ UPDATE db_file_info:{file_name} SET sesno={end_sesno}
│
└─ 返回 Ok(true)
```

**关键代码**:

```rust
pub async fn execute_incr_update(
    &self,
    increment_ranges_map: IndexMap<PathBuf, (DbPageBasicInfo, RangeInclusive<i32>)>,
) -> anyhow::Result<bool> {
    for (path, (basic_info, sesno_range)) in increment_ranges_map {
        println!("Path: {:?}, Sesno Range: {:?}", path, &sesno_range);

        // 1. 打开文件
        let mut io = PdmsIO::new("", path.clone(), true);
        io.open()
            .map_err(|e| anyhow::anyhow!("Failed to open PdmsIO: {}", e))?;

        // 2. 收集增量
        let end_sesno = sesno_range.end().clone();
        let range_update_eles = io.collect_increment_eles(Some(sesno_range))?;

        // 3. 更新数据库
        io.update_elements_to_database(&range_update_eles, true).await?;

        // 4. 更新会话号书签
        let file_name = path.file_stem().unwrap().to_str().unwrap();
        let sql = format!("UPDATE db_file_info:{} SET sesno={};", file_name, end_sesno);
        SUL_DB.query(sql).await.unwrap();
    }

    Ok(true)
}
```

## 4. 关键代码模块

### 4.1 会话号查询

**通过数据库编号查询** (`query_latest_sesno_by_dbnum`):

```rust
/// 通过数据库编号查询数据库中最新的会话号
///
/// # 参数
/// * `dbnum` - 要查询的数据库编号
///
/// # 返回值
/// * `anyhow::Result<u32>` - 成功则返回最新会话号,失败返回错误
async fn query_latest_sesno_by_dbnum(dbnum: u32) -> anyhow::Result<u32> {
    let mut response = SUL_DB
        .query(format!(
            r#"
            math::max(array::flatten([
                SELECT VALUE sesno FROM dbnum_info_table WHERE dbnum = {}
            ]));
            "#,
            dbnum
        ))
        .await?;
    let sesno: Option<u32> = response.take(0)?;
    Ok(sesno.unwrap_or_default())
}
```

**SQL说明**:
- 从 `dbnum_info_table` 查询指定 `dbnum` 的所有 `sesno`
- 使用 `math::max` 获取最大值
- 如果查询为空返回 0

**通过文件名查询** (`query_latest_sesno_by_file_name`):

```rust
async fn query_latest_sesno_by_file_name(file_name: &str) -> anyhow::Result<u32> {

            "#,
            file_name
        ))
        .await?;
    let sesno: Option<u32> = response.take(0)?;
```

### 4.2 去重检查查询

**查询逻辑**:

```rust
// 避免对已经同步过相同文件hash的记录重复发送
let sql = format!(
    "select value <string> id from (
        select * from e3d_sync
        where location != '{}'
        and '{}' in file_names
        and '{}' in file_hashes
        order by timestamp desc
    )",
    get_db_option().location.as_str(),
    file_name,
    &file_hash
);

let mut response = SUL_DB.query(&sql).await.unwrap();
let id = response.take::<Vec<String>>(0).unwrap();

if id.is_empty() {
    // 未找到重复，可以推送
    notify_file_names.push(file_name.to_owned());
    notify_file_hashes.push(file_hash);
}
```

**查询条件解析**:
1. `location != current`: 排除本地区的记录，避免自己同步给自己
2. `file_name in file_names`: 文件名匹配
3. `file_hash in file_hashes`: 哈希值匹配（确保内容相同）

### 4.3 MQTT推送

**带重试的推送逻辑**:

```rust
async fn publish_sync_payload_with_retry(
    client: AsyncClient,
    payload: SyncE3dFileMsg,
) -> anyhow::Result<()> {
    const MAX_RETRIES: usize = 3;

    for attempt in 1..=MAX_RETRIES {
        match client
            .publish("Sync/E3d", QoS::ExactlyOnce, true, payload.clone())
            .await
        {
            Ok(_) => {
                // 发布成功，记录消息
                #[cfg(feature = "web_server")]
                {
                    mqtt_monitor_handlers::record_message_sent(...).await;
                }
                return Ok(());
            }
            Err(err) => {
                if attempt == MAX_RETRIES {
                    return Err(anyhow::anyhow!(
                        "MQTT 发布失败 (重试 {} 次后仍未成功): {:?}",
                        attempt, err
                    ));
                } else {
                    println!("MQTT 发布失败 (第 {} 次)，准备重试: {:?}", attempt, err);
                    tokio::time::sleep(Duration::from_millis(500 * attempt as u64)).await;
                }
            }
        }
    }
    Ok(())
}
```

**重试策略**:
- 最多重试3次
- 重试间隔: 500ms * 尝试次数 (500ms, 1000ms, 1500ms)
- QoS: ExactlyOnce (确保消息只被接收一次)
- retain: true (保留最后一条消息)

```rust
// 添加重试和详细错误信息
async fn compress_with_retry(opts: CompressOptions, max_retries: usize) -> Result<String> {
    for attempt in 1..=max_retries {
        match execute_compress(opts.clone()).await {
            Ok(hash) => return Ok(hash.to_string()),
            Err(e) => {
                error!(
                    attempt = attempt,
                    max_retries = max_retries,
                    error = ?e,
                    input = %opts.input.display(),
                    output = %opts.output.display(),
                    "压缩失败"
                );

                if attempt < max_retries {
                    tokio::time::sleep(Duration::from_secs(2)).await;
                } else {
                    return Err(anyhow::anyhow!("压缩失败,已重试{}次: {:?}", max_retries, e));
                }
            }
        }
    }
    unreachable!()
}
```

### 8.4 性能问题

**问题**: 大量文件变化时处理缓慢

**可能原因**:
1. 同步执行,未并发处理
2. 数据库查询频繁
3. 大增量未分批处理

**优化方案**:

```rust
// 1. 并发处理多个文件
use futures::future::join_all;

let mut tasks = vec![];
for (path, header) in new_headers {
    let task = tokio::spawn(async move {
        process_file(path, header).await
    });
    tasks.push(task);
}

let results = join_all(tasks).await;

// 2. 使用缓存
let mut cache = SesnoCache::new(Duration::from_secs(5));
for dbnum in dbnums {
    let sesno = cache.get_or_query(dbnum).await?;
}

// 3. 分批处理
const BATCH_SIZE: i32 = 1000;
for chunk in (start..=end).collect::<Vec<_>>().chunks(BATCH_SIZE as usize) {
    execute_batch(chunk).await?;
}
```

### 8.5 数据不一致

**问题**: 数据库会话号与文件不同步

**可能原因**:
1. 增量更新失败但headers已更新
2. 数据库回滚未处理
3. 并发写入冲突

**解决方案**:

```rust
// 1. 事务性更新
async fn execute_incr_update_transactional(params: IncrementParams) -> Result<bool> {
    // 开始事务
    SUL_DB.query("BEGIN TRANSACTION;").await?;

    match process_increment(params).await {
        Ok(result) => {
            // 提交事务
            SUL_DB.query("COMMIT;").await?;

            // 只有成功后才更新headers
            for (path, header) in new_headers {
                self.watcher.headers.insert(path, header);
            }

            Ok(result)
        }
        Err(e) => {
            // 回滚事务
            SUL_DB.query("ROLLBACK;").await?;

            // 不更新headers
            Err(e)
        }
    }
}

// 2. 会话号回滚检测
if file_sesno < db_sesno {
    error!(
        file = %file_name,
        file_sesno = file_sesno,
        db_sesno = db_sesno,
        "检测到会话号回滚,可能是数据恢复操作"
    );

    // 记录告警
    alert_manager.send_alert(
        AlertLevel::Warning,
        format!("文件{}会话号回滚", file_name)
    );
}
```

## 10. 已知问题与优化建议

### 10.1 严重问题 (P0)

#### 问题1: 并发安全风险

**问题描述**:
- 代码位置: `increment_manager.rs:697-723`
- `watcher.headers.get_mut(path)` 长时间持有锁
- 持有锁期间执行数据库查询和压缩操作

**影响**:
- 其他文件变化事件被阻塞
- 可能导致死锁
- 性能下降

**修复建议**:

```rust
// 当前代码 (有问题)
if let Some(mut old) = self.watcher.headers.get_mut(path) {
    // ❌ 持有锁期间查询数据库
    let db_sesno = Self::query_latest_sesno_by_dbnum(db_num).await?;
    // ...
}

// 修复后代码
let old_sesno = {
    self.watcher.headers
        .get(path)
        .map(|h| h.latest_ses_data.sesno)
};

// 释放锁后查询
let db_sesno = Self::query_latest_sesno_by_dbnum(db_num).await?;

// 需要时重新获取锁
if new_sesno > db_sesno {
    self.watcher.headers.insert(path, new_header);
}
```

**优先级**: 🔴 高 (建议立即修复)

#### 问题2: 错误恢复缺失

**问题描述**:
- 多处使用 `continue` 跳过错误
- 临时故障导致增量永久丢失
- 无重试机制

**影响**:
- 数据一致性风险
- 增量丢失无法追踪

**修复建议**:

```rust
// 实现失败任务队列
pub struct FailedTask {
    pub path: PathBuf,
    pub error: String,
    pub retry_count: u32,
    pub last_attempt: SystemTime,
}

impl AiosDBManager {
    pub failed_tasks: Arc<RwLock<Vec<FailedTask>>>,
}

// 失败时记录
if let Err(e) = execute_compress(opts).await {
    self.failed_tasks.write().await.push(FailedTask {
        path: path.clone(),
        error: e.to_string(),
        retry_count: 0,
        last_attempt: SystemTime::now(),
    });
}

// 后台重试线程
tokio::spawn(async move {
    loop {
        tokio::time::sleep(Duration::from_secs(60)).await;
        retry_failed_tasks().await;
    }
});
```

**优先级**: 🔴 高

### 10.2 中等问题 (P1)

#### 问题3: 性能瓶颈

**问题描述**:
- 每次文件变化都查询数据库
- 无缓存机制
- 可能导致数据库过载

**优化建议**:

```rust
// 实现本地缓存
pub struct SesnoCache {
    cache: Arc<RwLock<HashMap<u32, (u32, Instant)>>>,
    ttl: Duration,
}

impl SesnoCache {
    pub async fn get_or_query(&self, dbnum: u32) -> Result<u32> {
        // 检查缓存
        {
            let cache = self.cache.read().await;
            if let Some((sesno, timestamp)) = cache.get(&dbnum) {
                if timestamp.elapsed() < self.ttl {
                    return Ok(*sesno);
                }
            }
        }

        // 查询并更新缓存
        let sesno = query_latest_sesno_by_dbnum(dbnum).await?;
        {
            let mut cache = self.cache.write().await;
            cache.insert(dbnum, (sesno, Instant::now()));
        }

        Ok(sesno)
    }
}
```

**优先级**: 🟡 中

#### 问题4: 代码复杂度高

**问题描述**:
- `async_watch()` 函数超过500行
- 新文件和增量更新逻辑混在一起
- 难以维护和测试

**优化建议**:

拆分为独立函数:
- `process_existing_file()` - 处理已存在文件
- `process_new_file()` - 处理新增文件
- `generate_and_check_archive()` - 生成压缩包并去重
- `publish_mqtt_notification()` - 发布MQTT消息

**优先级**: 🟡 中
