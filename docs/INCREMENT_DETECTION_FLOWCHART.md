## 三、子流程 A：增量元素收集与数据库更新

```
┌─────────────────────────────────────────────────────────────────┐
│         子流程 A: execute_incr_update (增量更新执行)             │
└─────────────────────────────────────────────────────────────────┘

START (params: HashMap<Path, (Header, Range<i32>)>)
  │
  ▼
┌─────────────────────────────────────────┐
│ 遍历每个有增量的数据库文件               │
│ for (path, (header, range)) in params   │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│ 1. 收集增量元素                          │
│  collect_increment_eles(path, range)    │
│  ┌─────────────────────────────────────┐│
│  │ 输入: range = 12341..=12350         ││
│  │                                     ││
│  │ 处理:                               ││
│  │ for sesno in range {                ││
│  │   - 读取该 sesno 的元素变更记录      ││
│  │   - 识别操作类型:                   ││
│  │     • Add (新增元素)                ││
│  │     • Modified (修改元素)           ││
│  │     • Deleted (删除元素)            ││
│  │ }                                   ││
│  │                                     ││
│  │ 输出: Vec<IncrementInfo>            ││
│  │ ┌─────────────────────────────────┐││
│  │ │ IncrementInfo {                 │││
│  │ │   refno: 12345,                 │││
│  │ │   db_no: 7997,                  │││
│  │ │   attr: {...属性映射...},       │││
│  │ │   children: [...子元素引用...], │││
│  │ │   operation: Add/Modified/...   │││
│  │ │ }                               │││
│  │ └─────────────────────────────────┘││
│  └─────────────────────────────────────┘│
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│ 2. 分类增量元素                          │
│  按操作类型分组                          │
│  ┌─────────────────────────────────────┐│
│  │ added_eles = increments             ││
│  │   .filter(|e| e.is_added())         ││
│  │                                     ││
│  │ modified_eles = increments          ││
│  │   .filter(|e| e.is_modified())      ││
│  │                                     ││
│  │ deleted_eles = increments           ││
│  │   .filter(|e| e.is_deleted())       ││
│  └─────────────────────────────────────┘│
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│ 3. 更新到 SurrealDB                      │
│  update_elements_to_database()          │
│  ┌─────────────────────────────────────┐│
│  │ // 新增元素                         ││
│  │ for ele in added_eles {             ││
│  │   INSERT INTO dbnum_info_table {    ││
│  │     refno: ele.refno,               ││
│  │     dbnum: ele.db_no,               ││
│  │     attr: ele.attr,                 ││
│  │     children: ele.children,         ││
│  │     sesno: current_sesno            ││
│  │   }                                 ││
│  │ }                                   ││
│  │                                     ││
│  │ // 修改元素                         ││
│  │ for ele in modified_eles {          ││
│  │   UPDATE dbnum_info_table           ││
│  │   SET attr = ele.attr,              ││
│  │       children = ele.children,      ││
│  │       sesno = current_sesno         ││
│  │   WHERE refno = ele.refno           ││
│  │ }                                   ││
│  │                                     ││
│  │ // 删除元素                         ││
│  │ for ele in deleted_eles {           ││
│  │   DELETE FROM dbnum_info_table      ││
│  │   WHERE refno = ele.refno           ││
│  │ }                                   ││
│  └─────────────────────────────────────┘│
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│ 4. 更新文件会话号记录                    │
│  ┌─────────────────────────────────────┐│
│  │ UPDATE db_file_info                 ││
│  │ SET sesno = file_sesno (12350)      ││
│  │ WHERE path = current_path           ││
│  └─────────────────────────────────────┘│
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│ 5. 更新内存缓存 (headers)                │
│  self.headers.insert(path, header)      │
└─────────────────┬───────────────────────┘
                  │
                  ▼
                 END
            返回主流程 (步骤 12)
```

## 四、子流程 B：压缩包生成与哈希计算

```
┌─────────────────────────────────────────────────────────────────┐
│         子流程 B: execute_compress (生成压缩包)                  │
└─────────────────────────────────────────────────────────────────┘

START (path: CATA.db)
  │
  ▼
┌─────────────────────────────────────────┐
│ 1. 确定输出路径                          │
│  ┌─────────────────────────────────────┐│
│  │ input = "D:/data/CATA.db"           ││
│  │ output = "assets/archives/CATA.cba" ││
│  │ temp_dir = "assets/temp"            ││
│  └─────────────────────────────────────┘│
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│ 2. 创建压缩选项                          │
│  CompressOptions::new(input, output,    │
│                       temp_dir)         │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│ 3. 执行压缩 (CBA 格式)                   │
│  ┌─────────────────────────────────────┐│
│  │ - 读取 PDMS 数据库文件               ││
│  │ - 应用压缩算法                       ││
│  │ - 写入 .cba 文件                     ││
│  └─────────────────────────────────────┘│
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│ 4. 计算文件哈希 (SHA256)                 │
│  ┌─────────────────────────────────────┐│
│  │ let mut hasher = Sha256::new();     ││
│  │ let bytes = fs::read(output)?;      ││
│  │ hasher.update(&bytes);              ││
│  │ let hash = hasher.finalize();       ││
│  │                                     ││
│  │ file_hash =                         ││
│  │   "abc123def456..."                 ││
│  │   (64位十六进制字符串)               ││
│  └─────────────────────────────────────┘│
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│ 5. 返回文件哈希                          │
│  return file_hash                       │
└─────────────────┬───────────────────────┘
                  │
                  ▼
                 END
            返回主流程 (步骤 13)
```

## 五、子流程 C：去重检查与 MQTT 推送

```
┌─────────────────────────────────────────────────────────────────┐
│         子流程 C: 去重检查与消息推送                             │
└─────────────────────────────────────────────────────────────────┘

START (file_name: "CATA", file_hash: "abc123...")
  │
  ▼
┌─────────────────────────────────────────┐
│ 1. 查询 e3d_sync 表                      │
│  ┌─────────────────────────────────────┐│
│  │ SELECT * FROM e3d_sync              ││
│  │ WHERE location != '当前地区'         ││
│  │   AND 'CATA' IN file_names          ││
│  │   AND 'abc123...' IN file_hashes    ││
│  │ ORDER BY timestamp DESC             ││
│  │                                     ││
│  │ // 排除本地区的记录，避免循环       ││
│  │ // 基于文件名+哈希组合去重          ││
│  └─────────────────────────────────────┘│
└─────────────────┬───────────────────────┘
                  │
                  ▼
          ┌───────────────┐
          │ 查询结果为空？ │
          └───────┬───────┘
           [否]   │   [是]
             │    │
      ┌──────┘    └──────┐
      │                  │
      ▼                  ▼
┌────────────┐   ┌─────────────────────────────────────────┐
│ 跳过推送    │   │ 2. 添加到推送列表                        │
│ (已存在)   │   │  notify_file_names.push("CATA")         │
└────────────┘   │  notify_file_hashes.push("abc123...")   │
                 └─────────────┬───────────────────────────┘
                               │
                               ▼
                 ┌─────────────────────────────────────────┐
                 │ 3. 构建 MQTT 消息                        │
                 │  SyncE3dFileMsg {                       │
                 │    file_names: ["CATA", ...],           │
                 │    file_hashes: ["abc123...", ...],     │
                 │    file_server_host: "http://...",      │
                 │    location: "bj",                      │
                 │    timestamp: 2025-11-18T12:34:56Z      │
                 │  }                                      │
                 └─────────────┬───────────────────────────┘
                               │
                               ▼
                 ┌─────────────────────────────────────────┐
                 │ 4. 保存到数据库 (e3d_sync)               │
                 │  INSERT IGNORE INTO e3d_sync {...}      │
                 │  // 记录本次推送，用于后续去重           │
                 └─────────────┬───────────────────────────┘
                               │
                               ▼
                 ┌─────────────────────────────────────────┐
                 │ 5. 发布到 MQTT                           │
                 │  mqtt_client.publish(                   │
                 │    topic: "Sync/E3d",                   │
                 │    qos: ExactlyOnce,                    │
                 │    retain: true,                        │
                 │    payload: SyncE3dFileMsg              │
                 │  )                                      │
                 └─────────────┬───────────────────────────┘
                               │
                               ▼
                 ┌─────────────────────────────────────────┐
                 │ 6. 其他站点接收消息                      │
                 │  订阅 "Sync/E3d" 的监听器触发            │
                 └─────────────┬───────────────────────────┘
                               │
                               ▼
                 ┌─────────────────────────────────────────┐
                 │ 7. 地区筛选                              │
                 │  if location in target_locations {      │
                 │    // 该站点需要同步此文件               │
                 │    创建下载任务                          │
                 │  }                                      │
                 └─────────────┬───────────────────────────┘
                               │
                               ▼
                 ┌─────────────────────────────────────────┐
                 │ 8. 任务入队                              │
                 │  enqueue_generated_sync_tasks()         │
                 │  ┌─────────────────────────────────────┐│
                 │  │ for target in targets {             ││
                 │  │   SyncTask {                        ││
                 │  │     source: "bj",                   ││
                 │  │     target: target,                 ││
                 │  │     file_url: "http://.../CATA.cba",││
                 │  │     file_hash: "abc123...",         ││
                 │  │     priority: Normal                ││
                 │  │   }                                 ││
                 │  │ }                                   ││
                 │  └─────────────────────────────────────┘│
                 └─────────────┬───────────────────────────┘
                               │
                               ▼
                              END
                         返回主流程 (步骤 15)
```

## 六、数据结构详解

```
┌─────────────────────────────────────────────────────────────────┐
│                     核心数据结构关系图                            │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────┐
│ DbPageBasicInfo (文件头部)               │
├─────────────────────────────────────────┤
│ + db_num: i32                           │  数据库编号 (7997)
│ + latest_ses_data: SessionData          │
│   └─ sesno: i32                         │  文件会话号 (12350)
│ + db_type: String                       │  数据库类型 (CATA)
│ + total_elements: u32                   │  元素总数
└─────────────────────────────────────────┘
                  │
                  │ 对比
                  ▼
┌─────────────────────────────────────────┐
│ dbnum_info_table (SurrealDB 表)         │
├─────────────────────────────────────────┤
│ + dbnum: i32                            │  数据库编号 (7997)
│ + sesno: i32                            │  数据库会话号 (12340)
│ + refno: u64                            │  元素引用号
│ + attr: NamedAttrMap                    │  元素属性
│ + children: Vec<u64>                    │  子元素引用
└─────────────────────────────────────────┘
                  │
                  │ 有增量时生成
                  ▼
┌─────────────────────────────────────────┐
│ IncrementInfo (增量元素)                 │
├─────────────────────────────────────────┤
│ + refno: u64                            │  元素引用号
│ + db_no: i32                            │  数据库编号
│ + attr: NamedAttrMap                    │  属性映射
│ + children: Vec<u64>                    │  子元素引用
│ + operation: EleOperation               │  操作类型:
│   ├─ Add                                │    - 新增
│   ├─ Modified                           │    - 修改
│   └─ Deleted                            │    - 删除
└─────────────────────────────────────────┘
                  │
                  │ 处理后生成
                  ▼
┌─────────────────────────────────────────┐
│ SyncE3dFileMsg (MQTT 消息)               │
├─────────────────────────────────────────┤
│ + file_names: Vec<String>               │  ["CATA", "PIPE"]
│ + file_hashes: Vec<String>              │  ["abc123...", "def456..."]
│ + file_server_host: String              │  "http://192.168.1.10:8080"
│ + location: String                      │  "bj"
│ + timestamp: SurrealDatetime            │  2025-11-18T12:34:56Z
└─────────────────────────────────────────┘
                  │
```

## 七、会话号对比核心逻辑

```
┌─────────────────────────────────────────────────────────────────┐
│              会话号对比与增量范围计算详解                         │
└─────────────────────────────────────────────────────────────────┘

场景 1: 正常增量更新
┌────────────────────────────────────────┐
│ 文件会话号: 12350                       │
│ 数据库会话号: 12340                     │
│                                        │
│ 判断: 12350 > 12340 ✅ 有增量           │
│                                        │
│ 增量范围: (12340 + 1)..=12350          │
│         = 12341..=12350                │
│         = [12341, 12342, ..., 12350]   │
│         = 10 个会话                    │
└────────────────────────────────────────┘

场景 2: 会话号不连续 (需要 get_nearest_large_sesno)
┌────────────────────────────────────────┐
│ 文件会话号: 12350                       │
│ 数据库会话号: 12340                     │
│ 文件实际会话号: [12340, 12345, 12350]  │
│                        ↑                │
│                    (跳号了，12341-12344│
│                     不存在)            │
│                                        │
│ 步骤 1: 查找最近会话号                  │
│   get_nearest_large_sesno(12341)      │
│   → 返回 12345 (最近的大于12341的sesno)│
│                                        │
│ 步骤 2: 构建增量范围                    │
│   range = 12345..=12350               │
│         = [12345, 12350]              │
│         = 2 个会话                     │
│                                        │
│ 效果: 跳过不存在的会话号，避免错误      │
└────────────────────────────────────────┘

场景 3: 无增量更新
┌────────────────────────────────────────┐
│ 文件会话号: 12340                       │
│ 数据库会话号: 12340                     │
│                                        │
│ 判断: 12340 == 12340 ⏭️ 无增量          │
│                                        │
│ 操作: continue (跳过此文件)             │
└────────────────────────────────────────┘

场景 4: 首次导入 (数据库为空)
┌────────────────────────────────────────┐
│ 文件会话号: 12350                       │
│ 数据库会话号: 0 (或 null)               │
│                                        │
│ 判断: 12350 > 0 ✅ 全量导入             │
│                                        │
│ 增量范围: 1..=12350                    │
│         = 全部历史会话                 │
│         = 完整数据导入                 │
└────────────────────────────────────────┘
```

## 九、性能优化建议

```
┌─────────────────────────────────────────────────────────────────┐
│                     性能瓶颈与优化方案                           │
└─────────────────────────────────────────────────────────────────┘

当前瓶颈                           优化方案
─────────────────────────────────────────────────────────────────

1. 数据库频繁查询
   ┌─────────────────────┐         ┌─────────────────────┐
   │ 每次文件变化都查询   │   →    │ 增加会话号缓存       │
   │ query_latest_sesno  │         │ TTL: 5 秒           │
   └─────────────────────┘         └─────────────────────┘

   ┌─────────────────────┐         ┌─────────────────────┐
   │ 持有锁期间查询DB     │   →    │ 查询前释放锁         │
   │ (可能阻塞数秒)      │         │ 查询后重新获取       │
   └─────────────────────┘         └─────────────────────┘

3. 超大增量内存溢出
   ┌─────────────────────┐         ┌─────────────────────┐
   │ 一次性加载所有增量   │   →    │ 分批处理             │
   │ (可能 50000+ 元素)  │         │ batch_size = 1000   │
   └─────────────────────┘         └─────────────────────┘

4. 错误静默失败
   ┌─────────────────────┐         ┌─────────────────────┐
   │ continue 跳过错误    │   →    │ 失败任务入队         │
   │ (可能丢失增量)      │         │ 定时重试             │
   └─────────────────────┘         └─────────────────────┘

5. 文件哈希重复计算
   ┌─────────────────────┐         ┌─────────────────────┐
   │ 每次都计算 SHA256    │   →    │ 缓存哈希结果         │
   │ (大文件耗时数秒)    │         │ 文件 mtime 作为key  │
   └─────────────────────┘         └─────────────────────┘
```
