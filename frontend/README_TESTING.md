# 增量更新前端测试快速指南

## 🚀 快速开始

### 方法 1: 使用启动脚本（推荐）

**Windows**:
```bash
# 在 web-server 根目录
start_dev_servers.bat
```

这会自动:
1. 启动前端开发服务器 (http://localhost:3000)
2. 启动后端 web 服务器 (http://localhost:8080)
3. 打开浏览器访问前端和测试页面

### 方法 2: 手动启动

**启动后端**:
```bash
# 终端 1 - 在 web-server 根目录
cargo run --bin web_server --features web_server
```

**启动前端**:
```bash
# 终端 2 - 在 web-server/frontend 目录
npm run dev
```

**访问**:
- 前端应用: http://localhost:3000
- 后端 API: http://localhost:8080
- WebSocket 测试: http://localhost:8080/test_websocket.html

## 🎯 验证 WebSocket 实时推送修复

### 关键验证点

**后端日志应包含**:
```
✅ ProgressHub 已注入到 SyncControlCenter
```
(在启动时出现，证明 ProgressHub 已正确注入)

**当文件发生变更时**，后端日志应包含:
```
发生了增量更新，推送：ams1112_0001
📡 已通过 WebSocket 推送增量更新通知给 1 个客户端: 检测到增量更新: 1 个文件 (会话范围: 1184-1184)
```

**前端 WebSocket 应收到消息**:
```json
{
  "task_id": "increment-1732001234567",
  "status": "Completed",
  "percentage": 100.0,
  "current_step": "检测到增量更新: 1 个文件 (会话范围: 1184-1184)",
  "message": "ams1112_0001"
}
```

## 🧪 测试步骤

### 1. 验证基础连接

打开 http://localhost:3000，检查:

- ✅ 页面正常加载（无报错）
- ✅ 右上角显示 "ONLINE" 绿色状态
- ✅ 侧边栏显示 "实时通知 开启"
- ✅ 能看到统计卡片和站点列表

### 2. 测试 WebSocket 实时推送

**使用测试页面**:

1. 打开 http://localhost:8080/test_websocket.html
2. 页面应自动连接（状态显示为"已连接"）
3. 点击 "获取任务列表" 按钮
4. 观察日志区域是否收到响应
5. 点击 "手动触发检测" 按钮
6. 观察是否收到实时进度消息

**预期消息流**:
```
🤝 握手成功: 多任务订阅连接成功
📋 任务列表更新 (0 个任务)
🔍 正在触发手动检测...
✅ 检测触发成功
🔄 [detect-xxx] Running: 50% - 正在扫描文件...
✅ [detect-xxx] Completed: 100% - 检测完成
```

### 3. 验证前端实时更新

回到前端界面 (http://localhost:3000):

**触发检测**:
1. 在站点卡片上找到 "检测变更" 按钮
2. 点击按钮
3. 观察界面变化

**预期行为**:
- Toast 通知弹出："开始检测变更"
- 站点状态变为 "Scanning"（黄色）
- 系统日志自动追加新记录
- 完成后状态变为 "Completed"（绿色）
- Toast 通知："任务 xxx 已完成"

### 4. 查看历史记录

1. 点击左侧边栏 "同步历史"
2. 应显示最新的同步记录
3. 包含文件名、时间戳、session 范围
4. 点击记录可查看详情

### 5. 查看系统日志

1. 点击左侧边栏 "系统日志"
2. 应显示实时日志流
3. 包含 INFO、SUCCESS、ERROR 等级别
4. 自动滚动到最新

## 🔍 调试技巧

### 浏览器开发者工具

**Network 标签** (查看 WebSocket):
1. 按 F12 打开开发者工具
2. 切换到 "Network" 标签
3. 筛选 "WS" (WebSocket)
4. 应看到 `tasks` 连接，状态 101
5. 点击连接查看消息流

**Console 标签** (查看日志):
```javascript
// 在控制台执行，查看 WebSocket 状态
console.log('WebSocket 状态:', window.ws?.readyState)

// 手动发送命令
window.ws?.send(JSON.stringify({ action: 'list' }))
```

### 后端日志

关键日志标识:
- `[WebSocket]` - WebSocket 相关
- `发现需要增量更新` - 检测到变化
- `✅` - 成功操作
- `❌` - 错误信息

### 常见问题

**问题**: 前端显示 "http proxy error"
**解决**: 确认后端已启动 (http://localhost:8080)

**问题**: WebSocket 连接失败
**解决**:
1. 检查后端日志是否有 `WebSocket 多任务连接请求`
2. 确认防火墙未阻止
3. 清除浏览器缓存重试

**问题**: 界面不更新
**解决**:
1. 检查浏览器控制台是否有错误
2. 验证 WebSocket 是否连接（Network 标签）
3. 手动刷新页面 (Ctrl+R)

## 📝 测试模拟场景

### 场景 1: 首次检测

**操作**: 启动服务器后首次访问

**预期**:
- 后端自动执行一次增量检测
- 前端显示最新状态
- 历史记录包含启动时的检测

### 场景 2: 手动触发检测

**操作**: 点击"检测变更"按钮

**预期**:
- 立即显示 Toast 通知
- 站点状态变为 Scanning
- WebSocket 推送进度消息
- 完成后状态变为 Completed

### 场景 3: PDMS 文件修改（真实场景）

**操作**:
1. 打开 PDMS/E3D
2. 修改任意元素并保存
3. 观察前端反应

**预期**:
- notify 监听器检测到文件变化
- 自动触发增量检测
- WebSocket 推送更新
- 前端自动刷新状态

### 场景 4: 网络断开重连

**操作**: 关闭后端服务器，然后重新启动

**预期**:
- 前端显示 "已断开" 状态
- Toast 通知："实时监听已断开，将尝试重连"
- 后端启动后自动重连
- 状态恢复为 ONLINE
