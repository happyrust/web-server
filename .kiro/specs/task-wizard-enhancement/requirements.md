# 任务向导增强需求文档

## 项目概述

基于 frontend 的 deploy-wizard 设计模式，为 EGUI 应用中的配置解析任务和模型生成任务创建统一的向导界面。

## 需求背景

当前 EGUI 应用中的任务创建流程存在以下问题：
1. 用户需要手动填写大量配置参数
2. 缺少步骤引导，容易遗漏关键配置
3. 没有配置验证和预览功能
4. 批量任务创建不够直观

参考 frontend 的 deploy-wizard 实现，我们需要创建一个分步骤的向导界面，提供更好的用户体验。

## 功能需求

### 1. 数据解析任务向导

#### 1.1 步骤 1: 项目扫描
- **需求**: 扫描指定目录，自动发现 PDMS 项目
- **输入**: 根目录路径
- **输出**: 项目列表（项目名称、路径、数据库数量、大小、最后修改时间）
- **交互**: 
  - 目录浏览器
  - 递归扫描选项
  - 扫描深度设置
  - 实时扫描进度

#### 1.2 步骤 2: 项目选择
- **需求**: 从扫描结果中选择要解析的项目
- **输入**: 扫描到的项目列表
- **输出**: 选中的项目列表
- **交互**:
  - 多选列表（支持全选/反选）
  - 项目详情预览
  - 数据库文件列表
  - 过滤和搜索功能

#### 1.3 步骤 3: 解析配置
- **需求**: 配置解析参数
- **输入**: 解析模式、数据库编号、参考号等
- **输出**: 解析配置对象
- **交互**:
  - 解析模式选择（全部/指定数据库/指定参考号）
  - 数据库编号输入（支持范围和列表）
  - 高级选项（并行处理、最大并发数）
  - 配置模板加载/保存

#### 1.4 步骤 4: 预览确认
- **需求**: 预览任务配置并确认创建
- **输入**: 所有配置信息
- **输出**: 创建的任务
- **交互**:
  - 配置摘要显示
  - 资源需求预估
  - 任务命名
  - 优先级设置
  - 创建/取消按钮

### 2. 模型生成任务向导

#### 2.1 步骤 1: 数据源选择
- **需求**: 选择已解析的数据作为模型生成的输入
- **输入**: 已解析的项目列表
- **输出**: 选中的数据源
- **交互**:
  - 项目列表（显示解析状态）
  - 数据完整性检查
  - 数据预览

#### 2.2 步骤 2: 生成选项
- **需求**: 配置模型生成参数
- **输入**: 生成选项（3D模型、网格、空间树、布尔运算）
- **输出**: 生成配置对象
- **交互**:
  - 生成选项复选框
  - 网格容差滑块
  - 质量预设（快速/平衡/高质量）
  - 高级选项折叠面板

#### 2.3 步骤 3: 性能配置
- **需求**: 配置性能相关参数
- **输入**: 并发数、内存限制、优化选项
- **输出**: 性能配置对象
- **交互**:
  - 最大并发数滑块
  - 内存限制输入
  - 并行处理开关
  - 性能预估显示

#### 2.4 步骤 4: 预览确认
- **需求**: 预览任务配置并确认创建
- **输入**: 所有配置信息
- **输出**: 创建的任务
- **交互**:
  - 配置摘要显示
  - 资源需求预估
  - 预计耗时显示
  - 创建/取消按钮

## 非功能需求

### 3.1 用户体验
- **进度指示**: 清晰的步骤指示器，显示当前步骤和完成进度
- **导航**: 支持前进/后退，可以随时修改之前的配置
- **验证**: 实时验证输入，提供友好的错误提示
- **帮助**: 每个步骤提供帮助文本和示例

### 3.2 性能
- **响应性**: UI 操作响应时间 < 100ms
- **扫描速度**: 目录扫描支持异步，不阻塞 UI
- **内存占用**: 向导界面内存占用 < 50MB

### 3.3 可维护性
- **模块化**: 每个步骤独立组件，易于扩展
- **可复用**: 通用组件可在其他向导中复用
- **可测试**: 关键逻辑可单元测试

## 参考设计

### Frontend Deploy Wizard 特点
1. **清晰的步骤指示器**: 显示当前步骤、已完成步骤、总步骤数
2. **进度条**: 可视化显示完成进度
3. **步骤内容卡片**: 每个步骤独立的卡片容器
4. **导航按钮**: 统一的前进/后退/取消按钮
5. **数据流管理**: 使用 state 管理向导数据
6. **步骤组件化**: 每个步骤独立组件

### 需要适配的差异
1. **UI 框架**: React → EGUI
2. **状态管理**: React hooks → Rust struct
3. **异步处理**: Promise → tokio async
4. **样式系统**: CSS → EGUI 样式

## 技术约束

### 5.1 EGUI 限制
- 不支持 CSS 样式，需要使用 EGUI 的样式系统
- 布局系统与 Web 不同，需要适配
- 异步操作需要特殊处理

### 5.2 Rust 约束
- 所有权和借用规则
- 异步编程模型
- 类型系统严格

### 5.3 集成约束
- 需要与现有 API 客户端集成
- 需要与现有任务管理系统集成
- 需要与现有状态管理集成

## 优先级

### P0 (必须实现)
- 数据解析任务向导基本流程
- 项目扫描和选择
- 基本配置和预览

### P1 (重要)
- 模型生成任务向导
- 高级配置选项

### P2 (可选)

- 任务模板管理
